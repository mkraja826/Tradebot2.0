# Dashboard-only release procedure
The branch is recover-trading-foundation, independent of legacy main. Verify the exact commit's offline and browser CI jobs. Do not switch the active trading checkout or restart trading workers. Use a separate pinned checkout (for example /opt/recover-dashboard/releases/<commit>) with read access for the dashboard service account. Inspect systemctl cat recover-dashboard.service and systemctl show recover-dashboard.service -p ExecStart -p WorkingDirectory -p User locally before selecting the existing data directory, port, and service identity. The checked-in preview unit uses preview journals and port 18766; do not replace actual deployed demo journal paths with those defaults. Never expose credentials or change broker settings. Stage the pinned checkout with a temporary loopback-only test port if permitted; check /api/overview, /api/chart and all assets. Update only the dashboard service WorkingDirectory (and its executable path if necessary) to the pinned release while retaining its current journal path and loopback binding. Restart only the dashboard service after daemon-reload; verify local HTTP responses and existing authenticated route/SSH forwarding. If unhealthy, revert only the dashboard service's release path and restart it. Confirm the existing trading workers remain running before and after. No changes to trading engine or account settings. Actual server access and deployment verification are required; a GitHub commit is not a deployment.
