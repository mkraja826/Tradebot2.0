# Provider reliability telemetry
Strict JSON decoding rejects duplicate keys and nonfinite constants; no repair or extraction of partial proposals. Record safe phase and response size, first headers latency and total network time, and retain success metrics separately from executable proposal. Wrapped transport timeouts use the existing single recovery policy; no additional immediate retries, model fallback, trading setting or order retry. HTTP 520 remains unresolved upstream and is not added to the retry list. Success and failure telemetry are reported separately; earlier successful requests lack telemetry. No live provider probe or extra order.
